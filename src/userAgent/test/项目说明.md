## 1. 项目定位

**ZTrust 零信任访问控制系统客户端** —— 桌面端终端（User Agent）。

核心职责有三块：

1. **用户认证**：公司地址 + 用户名密码 + 安全码（安全码用于 SPA 单包授权，SPA 端口开放后才允许访问业务系统）
2. **资源访问代理**：用户在 UI 点击"资源"，客户端向服务端申请访问授权，通过鉴权后在独立 WebView 窗口中打开该资源
3. **行为采集**：持续采集设备安全上下文 + 用户操作行为，批量上报服务端供风控评分

一句话概括：**它是"用户点资源 → 客户端负责鉴权与开门 → 在受控窗口里打开 → 全程留痕"的终端工具。**

## 5. 核心业务流程

### 5.1 登录流程（`views/Login/index.vue`，862 行，最复杂的页面）

分两步：

```
第 1 步：输入公司地址
   → 校验地址格式（utils/request/index.js 中的 isValidBaseURL）
   → 存入 localStorage.companyAddress
   → 拉取该租户的登录页动态配置（logo、文案、是否需要安全码等）

第 2 步：用户名 + 密码（+ 安全码）
   → POST /auth/login
   → 安全码 → SPA 报文发送（见 5.2）
   → 保存 token 到 Tauri store，securityCode 存系统密钥库
```

**登录态的两套存储（务必理解）**：

| 位置 | 内容 | 生命周期 |
|---|---|---|
| `sessionStorage.auth_token` | JWT token | 会话级，退出即清 |
| `localStorage.ztrust.session_id` | 服务端下发的 session_id | 跨会话持久 |
| `localStorage.ztrust.auth_strength` | `password` 或 `password+security_code` | 跨会话持久 |
| `localStorage.ztrust_device_id` | 设备 ID | 持久（设备级） |
| Tauri store `settings.json` | access_token / auth_token / securityCode / deviceFingerprint / licenseId / deviceToken | 持久 |
| 系统密钥库（keyring） | 安全码、记住的用户名密码 | 持久 |

> `device_id` / `device_token` 是**设备级凭证**，登出时**不清除**（`api/auth.js` 的 `clearSession` 注释明确说明），因为下次登录还要用它们做设备可信判断。

**降级与异常分支**（Login 页已处理，接手后改动需留意）：

- `needSecurityCode` —— 服务端判定设备不可信时，要求补输安全码
- `deviceUntrustedNotice` —— 本地有 id+token 但服务端拒绝
- `deviceTokenInvalidDialog` —— device_token 失效弹窗
- `autoLoginAfterCompanySubmit` —— 登录失败退回第 1 步重输地址后，自动接着重试登录

### 5.2 SPA 单包授权（`src-tauri/src/spa.rs` + `utils/spa/index.js`）

这是零信任网关开门的关键，**协议必须与服务端严格一致**，改动前务必确认。

流程：

1. 用户输入安全码（token_code，如 `2345-6789-ABCD`）
2. Base32 解码 → HKDF-SHA256（salt=`zerotrust-spa`, info=`spa-token`）派生 32 字节 **SpaKey**
3. 解析 DeviceID（32 字节）与 LicenseID（16 字节），**兼容历史长度**（16 字节 SHA256 扩展到 32，8 字节扩展到 16）
4. 组装 56 字节明文 Payload：`[时间戳(8, BE) | DeviceID(32) | LicenseID(16)]`
5. AAD（29 字节）= `version(1) | userHint(16，取 SpaKey 前16字节) | nonce(12)`
6. **AES-256-GCM** 加密
7. 组包：`[version(1) | userHint(16) | nonce(12) | ciphertext | authTag(16)]`
8. **UDP** 发送至 `服务器host:41234`（端口在前端 `utils/spa/index.js` 硬编码 `SPA_PORT = 41234`）

**发送时机**：
- 登录时发送一次
- 点击资源前（`ensureSpaSent({ reason: 'resource-click' })`）
- 后台心跳，每 3 分钟一次（`startSpaHeartbeat`）

> **设计约定**：资源访问时不再重发 SPA（`lib.rs` 第 163 行注释），因为端口开放后持续有效。
> **并发去重**：`ensureSpaSent` 用模块级 `inflight` 变量合并并发请求。
> **非 Tauri 环境直接跳过**，避免浏览器调试时被网关拦截。

⚠️ **硬编码值（需上线前处理）**：`utils/spa/index.js` 中的 `DEFAULT_LICENSE_ID = '7f8e3d2a1c9b4e6f5a0d8c2b7e4f1a3c'` 是写死的许可证 ID。

### 5.3 资源访问流程（关键链路）

```
用户点击资源
  → POST /auth/access/{resourceId}   （带 token / session_id / device_id / tenant_id）
  → 服务端返回授权
  → invoke('open_resource_window', { resourceId, title, baseUrl })
       ↓ Rust 侧
       从 Tauri store 读取 access_token / securityCode / deviceFingerprint / licenseId
       deviceId 经 normalize_hex_value() + upgrade_to_64_hex() 规范化到 64 字符 hex
       label = "resource_<uuid去连字符>"
       debug: http://localhost:5173/resource-proxy.html?baseUrl=...&authToken=...
       prod : resource:///resource-proxy.html?baseUrl=...&authToken=...
       创建独立 WebviewWindow（1024×700，可缩放，居中）
  → resource-proxy.html 内嵌 iframe 加载真实业务系统
```

关闭资源窗口走 `close_resource_window`，会顺带向活动监控记录 `record_resource_close`。

### 5.4 行为监控（`activity.rs` + `tauriActivityMonitor.js` + `sessionActivityCollector.js`）

三套机制，职责不同：

**(a) Rust 侧 `ActivityMonitor`** —— 持久化与上传
- 配置（`lib.rs` `activity_init` 中硬编码）：采样 100ms；**保存 2 分钟 / 上传 3 分钟**；单批上限 10000；失活超时 6 分钟
- 数据落 SQLite 表 `activity_records`，按 `batch_id` 批次管理，`uploaded` 标记是否已上报
- 上传成功后前端调 `activity_mark_batch_uploaded` 清除已上传记录
- 内置**滑动窗口频率统计**（`FrequencyStats`）：1 分钟 / 5 分钟 / 1 小时 / 24 小时

**(b) 前端 `sessionActivityCollector`** —— 轻量打点 + 周期 flush
- 事件类型：`access_attempt`、`access_granted`、`access_denied`、`access_error`、`logout`
- `utils/request/index.js` 的 axios 拦截器**自动**为所有 `/auth/access/*` 请求打点
- 登出时 `flushNow()` 立即上报，不等周期
- 上报接口：`POST /context/process`

**(c) 语义映射命令**（前端采集 → Rust 分类）
- `activity_record_shortcut` / `activity_record_command` / `activity_record_file` / `activity_record_resource_open`
- Rust 侧映射为四种操作类型：`Read`（浏览）、`Write`（键盘输入/编辑）、`Delete`、`Execute`（命令/快捷键）
- **采集端做语义映射，控制器（服务端）负责风险评分** —— 客户端不上报原始鼠标坐标做评分决策

**(d) 前端 raw 采集 composables**（`modules/behaviorCollector/`）：鼠标轨迹、键盘、页面时序、设备指纹，以及 `fingerprintSimilarity.js` 相似度计算。当前采样默认 50ms（config.js），与 Rust 的 100ms **不一致**。

### 5.5 设备上下文采集（启动时后台执行）

`setup` 钩子中 `spawn_background_collection()` 启动独立线程，**不阻塞窗口创建和登录**：

1. `device::generate_device_info()` —— 耗时最长（PowerShell + netsh + 公网 IP 探测）
2. `wifi::scan_top_wifi_networks(5)` —— 扫描前 5 个 Wi-Fi

两者结果写入 `AppState.device_info` / `wifi_cache`。前端 `get_device_info` / `scan_wifi_environment` **优先读缓存**，缓存未就绪才同步兜底采集。

**采集终端会打印一个可视化框**（`print_device_context` / `print_wifi_context`），8 个字段：

```
① 设备ID  ② 设备类型  ③ OS版本与补丁  ④ 防火墙
⑤ 磁盘加密  ⑥ Root/越狱状态  ⑦ 已安装软件  ⑧ 网络位置
```

设备安全上下文（`device_security.rs`）采集：
- **磁盘加密**：Windows 用 `Get-BitLockerVolume`，失败降级 `manage-bde`；macOS FileVault；Linux LUKS
- **安全状态**：UAC / SIP / SafeBoot / 实时保护
- **已安装软件清单**：注册表/包管理器统计

**公网 IP 与地理位置**：`get_login_session_info` → `ipify.org`（失败降级 `ifconfig.me`）→ `ip-api.com`（失败降级 `ip.sb`）→ 拼音转中文（`pinyin_to_chinese`）。

## 7. 安全相关（重点）

### 权限模型

`src-tauri/capabilities/default.json` 显式声明所有 IPC 权限，作用域为 `["main", "resource_*"]`。**新增前端调用若报权限错误，先检查此处。**

### 凭据存储分层

| 数据 | 存储 | 理由 |
|---|---|---|
| 安全码、用户名、密码 | **系统密钥库**（Windows 凭据管理器） | 不落 localStorage |
| token | Tauri store + sessionStorage | 双写，兼容不同读取点 |
| DeviceID / LicenseID | Tauri store | 设备级，登出保留 |

`keyringService.js` 的 `clearLocalStorageCredentials()` 是**向后兼容清理**，用于清掉历史遗留的明文敏感数据 —— 接手后若发现 localStorage 里还有旧凭据残留，调用它。

### CSP 配置风险（**建议尽快收紧**）

`tauri.conf.json` 当前：

```
default-src 'self' *; script-src 'self' 'unsafe-inline' 'unsafe-eval' *; style-src 'self' 'unsafe-inline' *; img-src 'self' data: blob: https: *; connect-src 'self' http://localhost:* https://* http://* ws://localhost:*; font-src 'self' data: *; frame-src *
```

问题：`script-src` 允许 `unsafe-inline` + `unsafe-eval` 且带 `*` 通配 —— 这基本抵消了 CSP 对 XSS 的防护作用。`connect-src` 与 `frame-src` 的 `*` 也放得很开（资源代理需要加载内网业务系统，放宽有业务原因，但 `script-src` 仍有收紧空间）。

### 其他注意点

- `Cargo.toml` 中 `tauri` 启用了 **`devtools` feature**，生产构建前确认是否需要关闭
- `panic = "abort"`：Rust panic 直接终止进程，不会走优雅退出
- `src-tauri/target/` 与 `gen/schemas/` 不应手工修改

## 8. 数据存储

### SQLite

路径：`%LOCALAPPDATA%\ZTrust\data\ztrust.db`（通过 `dirs::data_local_dir()`）

主要表：
- `activity_records` —— 行为记录（`batch_id` / `record_type` / `content` / `uploaded`），已建 3 个索引
- `device_info` —— 设备指纹与最后登录时间
- （`database.rs` 中还有用户数据清理相关表，`db_clear_user_data` 命令负责清空）

### Tauri store

## 10. 开发注意事项

### 代码风格

- 中文注释为主，日志前缀统一：`[SPA]`、`[Activity]`、`[DeviceInfo]`、`[Router]`、`[Request]`、`[Auth]`、`[Keyring]`、`[Startup]`、`[Window]`、`[WifiEnvironment]`
- 前端日志较多，调试时用 DevTools Console 过滤前缀即可
- Rust 日志级别 `Info`，通过 `env_logger` 输出

### 热更新限制

`vite.config.js` 中 `server.watch.ignored: ['**/src-tauri/**']` —— **修改 Rust 代码需要重启 `npm run tauri:dev`**，不会热更新。

### 调试建议

| 场景 | 方法 |
|---|---|
| 只调前端页面 | `npm run dev` + 浏览器（注意 SPA 和 keyring 在非 Tauri 环境会跳过） |
| 调 Rust 逻辑 | `npm run tauri:dev` + 看终端日志 |
| 调 Tauri 命令 | 安装 `rust-analyzer` 扩展，用其 Debug 配置 |
| 查设备采集结果 | 应用启动时终端打印的 8 字段框 |
| 查行为数据 | SQLite `activity_records` 表 |

### 加功能的常见落点

- **新页面** → `views/` 加组件 → `router.js` 注册路由
- **新 UI 控件** → `components/CustomUI/` 下按 `index.vue` 模式新增
- **新接口调用** → `utils/request/index.js` 导出方法复用
- **新采集行为** → `modules/behaviorCollector/composables/` 加 composable → 在 `tauriActivityMonitor.js` 接入 → 需要风险分类则在 Rust 加 `record_*` 命令
